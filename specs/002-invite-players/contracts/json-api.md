# Contract: JSON:API surface for Invite Players

**Feature**: 002-invite-players
**Data model**: [../data-model.md](../data-model.md)

This document describes the JSON:API routes generated by the
`json_api` blocks on `GameNight.Games.Player`,
`GameNight.Games.Invitation`, and `GameNight.Notifications.Notification`,
wired through `GameNightWeb.AshJsonApiRouter`. The generated
OpenAPI spec is the enforced source of truth; this file exists so
planning and review can happen without diffing the regenerated
OpenAPI on every change.

## Mount point

- Domains: `GameNight.Telemetry`, `GameNight.Games`,
  `GameNight.Notifications` registered in
  `GameNightWeb.AshJsonApiRouter`.
- All routes are reached under `/api/json/**`, mounted via the
  existing `forward "/", GameNightWeb.AshJsonApiRouter` in the `/api`
  scope.
- Pipeline: existing `:json_api_browser` (session-aware, sets actor).
  No new pipeline.

## `Player` routes

`json_api do` block on `GameNight.Games.Player`:

```elixir
json_api do
  type "player"

  routes do
    base "/players"

    index :list_for_game, route: "/by-game/:game_id"
    index :list_for_gm,   route: "/by-game/:game_id/gm"
    index :list_mine,     route: "/mine"
    patch :update
  end
end
```

| Method | Path                                       | Action            | Notes                                                                  |
|--------|--------------------------------------------|-------------------|------------------------------------------------------------------------|
| GET    | `/api/json/players/by-game/:game_id`       | `:list_for_game`  | Returns the game's roster. Admits GM and any seated player. Excludes `gm_notes`. |
| GET    | `/api/json/players/by-game/:game_id/gm`    | `:list_for_gm`    | Same shape but **GM-only** and includes `visible_gm_notes`.            |
| GET    | `/api/json/players/mine`                   | `:list_mine`      | The actor's own Player rows.                                           |
| PATCH  | `/api/json/players/:id`                    | `:update`         | GM-only.                                                               |

### Example: `GET /api/json/players/by-game/:game_id`

```http
GET /api/json/players/by-game/4d3f… HTTP/1.1
Accept: application/vnd.api+json
```

```json
{
  "data": [
    {
      "type": "player",
      "id": "9aa…",
      "attributes": {
        "character_name": "Mira Stoneheart",
        "character_summary": "Half-orc paladin, oath of devotion.",
        "status": "active",
        "inserted_at": "2026-04-26T14:08:11.000Z",
        "updated_at": "2026-04-26T14:08:11.000Z"
      },
      "relationships": {
        "user": { "data": { "type": "user", "id": "uu…" } },
        "game": { "data": { "type": "game", "id": "4d3…" } }
      }
    }
  ]
}
```

`gm_notes` is **not** present in this response. To retrieve it, the
GM uses `/by-game/:game_id/gm` instead.

### Example: `PATCH /api/json/players/:id`

```json
{
  "data": {
    "type": "player",
    "id": "9aa…",
    "attributes": {
      "status": "done",
      "gm_notes": "Retired after the Strahd campaign — Mira's player is on hiatus."
    }
  }
}
```

The PATCH accepts `character_name`, `character_summary`, `gm_notes`,
and `status`. Only the GM of the player's game can succeed. Any
other authenticated caller receives `404` (the policy makes
"forbidden" indistinguishable from "not found", per existing pattern).

## `Invitation` routes

`json_api do` block on `GameNight.Games.Invitation`:

```elixir
json_api do
  type "invitation"

  routes do
    base "/invitations"

    index :list_pending_for_game, route: "/by-game/:game_id/pending"
    index :list_pending_for_me,   route: "/mine/pending"
    post  :create_for_game,       route: "/"
    patch :accept_with_token,     route: "/:id/accept"
    patch :decline_with_token,    route: "/:id/decline"
    patch :revoke,                route: "/:id/revoke"
    route :preview_with_token, :get, route: "/preview/:token"
  end
end
```

| Method | Path                                           | Action                  | Notes                                                                   |
|--------|------------------------------------------------|-------------------------|-------------------------------------------------------------------------|
| GET    | `/api/json/invitations/preview/:token`         | `:preview_with_token`   | Public (token-bearer auth). Returns minimal preview data; never mutates.|
| GET    | `/api/json/invitations/by-game/:game_id/pending` | `:list_pending_for_game` | GM-only.                                                              |
| GET    | `/api/json/invitations/mine/pending`           | `:list_pending_for_me`  | Logged-in user; matches by their `email`.                               |
| POST   | `/api/json/invitations`                        | `:create_for_game`      | GM-only. Body includes `game_id`, `email`, `character_name`, `character_summary`, `gm_notes`. |
| PATCH  | `/api/json/invitations/:id/accept`             | `:accept_with_token`    | Logged-in user. Body carries `token`.                                   |
| PATCH  | `/api/json/invitations/:id/decline`            | `:decline_with_token`   | Logged-in user. Body carries `token`.                                   |
| PATCH  | `/api/json/invitations/:id/revoke`             | `:revoke`               | GM-only. No body.                                                       |

### Example: `POST /api/json/invitations`

```json
{
  "data": {
    "type": "invitation",
    "attributes": {
      "email": "rachel@example.com",
      "character_name": "Mira Stoneheart",
      "character_summary": "Half-orc paladin.",
      "gm_notes": "Rachel's first time playing a paladin — be patient."
    },
    "relationships": {
      "game": { "data": { "type": "game", "id": "4d3…" } }
    }
  }
}
```

Response (201): the created invitation with `status: "pending"` and
`expires_at`. The token is **not** returned in the response — it
exists only in the email body. (Returning the token would defeat the
"only the email recipient can accept" guarantee for any third party
who can read the GM's API responses.)

### Example: `GET /api/json/invitations/preview/:token`

```http
GET /api/json/invitations/preview/eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXV… HTTP/1.1
```

Response (200):

```json
{
  "data": {
    "type": "invitation_preview",
    "id": "<invitation-id>",
    "attributes": {
      "game_title": "Curse of Strahd",
      "inviter_email": "matt@example.com",
      "character_name": "Mira Stoneheart",
      "expires_at": "2026-05-26T14:08:11.000Z"
    }
  }
}
```

Response (404 / `invalid_token` error code) when the token is
invalid, expired, or revoked, or when the underlying invitation is
in a terminal state.

### Example: `PATCH /api/json/invitations/:id/accept`

```json
{
  "data": {
    "type": "invitation",
    "id": "<invitation-id>",
    "attributes": {
      "token": "eyJhbGciOiJIUzI1NiIs…"
    }
  }
}
```

Response (200): the invitation with `status: "accepted"` and
`accepted_player` relationship populated.

## `Notification` routes

`json_api do` block on `GameNight.Notifications.Notification`:

```elixir
json_api do
  type "notification"

  routes do
    base "/notifications"

    index :list_mine, route: "/"
    route :count_unread, :get, route: "/unread-count"
    patch :mark_read
  end
end
```

| Method | Path                                       | Action          | Notes                                                                        |
|--------|--------------------------------------------|-----------------|------------------------------------------------------------------------------|
| GET    | `/api/json/notifications`                  | `:list_mine`    | Optional query param `?filter[unread_only]=true`. Sort `inserted_at DESC`.   |
| GET    | `/api/json/notifications/unread-count`     | `:count_unread` | Returns a single-row response with the unread count. Drives the bell badge.  |
| PATCH  | `/api/json/notifications/:id`              | `:mark_read`    | Sets `read_at`. Idempotent (no-op if already read).                          |

System actions (`:create_for_invitation`, `:resolve_for_subject`)
are **not** exposed on JSON:API — they are internal to the
`GameNight.Notifications.System` context.

## Errors

All error responses follow the JSON:API error envelope and map to
stable codes:

| Status | Code                   | When                                                                                  |
|--------|------------------------|---------------------------------------------------------------------------------------|
| 401    | `not_authenticated`    | No session.                                                                           |
| 403    | `forbidden`            | Specific to `:preview_with_token` — never returned by other actions (which use 404 to avoid existence-leakage). |
| 404    | `not_found`            | Resource does not exist OR exists but the policy denies access.                       |
| 409    | `conflict`             | Duplicate-invitation on the same game/email; double-accept on a terminal invitation. |
| 422    | `invalid_attribute`    | Validation failure (e.g., empty email, invalid status).                               |
| 422    | `invalid_token`        | Token verification failed (signature, expiration, revocation, or wrong purpose).      |

## OpenAPI

`open_api_spex` regenerates the OpenAPI 3 document on compile. The
drift gate (`mix ash.codegen --check` + `mix ash_typescript.codegen`
+ `git diff --exit-code`) ensures the committed spec matches the
live resources.

## Test strategy

- **Request-level tests** (per resource, in
  `test/game_night_web/controllers/`): one authorized case and one
  unauthorized case per route. Each test uses `Phoenix.ConnTest.conn`
  through the real endpoint.
- **Email-side tests** (in `test/game_night/games/invitation_test.exs`):
  use Swoosh's `assert_email_sent` to verify the invitation email is
  enqueued with the correct token URL. The token is then used to
  drive an `accept_with_token` action and the resulting Player is
  asserted on.
- **Cross-resource read tests** (in `test/game_night/games/game_test.exs`):
  an accepted Player can `:get_mine` the game; a non-Player non-owner
  cannot.
- **Policy tests** (per resource): the unauthorized path is exercised
  for every action (different user, anonymous caller, non-GM trying
  to read GM-only routes).
