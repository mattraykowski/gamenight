# Phase 1 Data Model: Game Schedule

This document specifies the four new Ash resources that compose the schedule feature, their attributes, calculations, relationships, action surface, and policy matrix. It is the source of truth for the migration generated by `mix ash.codegen` and for the regenerated TypeScript client from `mix ash_typescript.codegen`.

All resources live under domain `GameNight.Schedules` (new). Cross-domain references resolve to existing resources:

- `GameNight.Games.Game`
- `GameNight.Games.Player` (the character-in-game association from feature 002)
- `GameNight.Notifications.Notification` (extended with four new `kind` values)

---

## Resource: `GameNight.Schedules.Schedule`

Represents one month's schedule for one game.

### Attributes

| Name | Type | Constraints | Notes |
| --- | --- | --- | --- |
| `id` | `:uuid` | primary key, default `Ash.UUID.generate/0` | |
| `game_id` | `:uuid` | required, FK → `games.id`, ON DELETE CASCADE | belongs_to `:game` |
| `month` | `:integer` | required, 1..12 | |
| `year` | `:integer` | required, ≥ 2024 (sanity bound; the in-the-past validation lives on the action) | |
| `start_time` | `:time` | required | `~T[19:00:00]` literal style |
| `end_time` | `:time` | required | may be < `start_time` (midnight crossing allowed per FR-007) |
| `time_zone` | `:string` | required, validated against `Tzdata` known-zones | IANA name, captured from GM browser at initiate |
| `status` | `:atom` | required, default `:preparing`, constraint `one_of: [:preparing, :ready_for_availability, :posted]` | state machine; transitions enforced by actions |
| `posted_at` | `:utc_datetime_usec` | nullable | set by `:post`; null until then |
| `inserted_at` | `:utc_datetime_usec` | timestamp | |
| `updated_at` | `:utc_datetime_usec` | timestamp | |

### Calculations (derived; not stored)

| Name | Type | Source | Public? | Loaded by default? |
| --- | --- | --- | --- | --- |
| `name` | `:string` | `GameNight.Schedules.Calculations.Name` | yes | yes |
| `submission_count` | `:integer` | `expr(count(participants, query: [filter: expr(np_only == false and not is_nil(submitted_at))]))` | yes | no (loaded by table view) |
| `participant_count` | `:integer` | `expr(count(participants, query: [filter: expr(np_only == false)]))` | yes | no |

`name` example output: `"October 2026 7:00 PM – 11:00 PM"`. Implementation calls `Calendar.strftime/2` on a synthesized `~D[year-month-01]` for the month name, then formats `start_time`/`end_time` with `:hour12` AM/PM.

### Relationships

- `belongs_to :game, GameNight.Games.Game` (required)
- `has_many :schedule_days, GameNight.Schedules.ScheduleDay`
- `has_many :participants, GameNight.Schedules.ScheduleParticipant`

### Identities

- `unique_per_game_month`: `[:game_id, :year, :month]` — enforces FR-002.

### Actions

| Name | Type | Args | Notes |
| --- | --- | --- | --- |
| `:initiate` | create | `month`, `year`, `start_time`, `end_time`, `time_zone`, `game_id` (relation) | Validates not-in-past per §8 of research.md. Spawns one `ScheduleDay` per day in the month with `gm_status: :NA`. |
| `:list_for_game` | read | filter on `game_id`; sort `year DESC, month DESC` | GM-only. Pagination supported (default limit 6 for the dashboard table; full list returns all). |
| `:list_for_game_top_six` | read | as above, prepared with `limit: 6` | GM-only, dedicated for the View Game table widget. |
| `:get_for_game` | read | scoped by `id` and `game_id` | GM-only; loads `schedule_days` and `participants` lazily. |
| `:set_gm_day` | update (multi-resource via `change`) | `day :: 1..31`, `status :: :NA \| :I \| :A \| :IF` | Asserts `schedule.status in [:preparing, :ready_for_availability]` (rejects with the message "GM availability is locked once a schedule is posted." when `:posted`). Updates the matching `ScheduleDay.gm_status`. If the new value is `:NA` and `schedule.status == :ready_for_availability`, applies `CascadeGmNa` change to overwrite every linked `ParticipantDay` for the same day. |
| `:transition_to_ready_for_availability` | update | none | Asserts `status == :preparing`. Applies `LinkActivePlayers` change (creates `ScheduleParticipant` per accepted Player, plus per-day NA rows). Applies `fan_out_notification(:schedule_ready_for_availability)`. Sets `status` to `:ready_for_availability`. Idempotent under retry. |
| `:post` | update | none | Asserts `status == :ready_for_availability`. Applies `ComputeFinalDefault` change (fills any null `final_status` per the truth table — see [research.md §4](./research.md)). `ComputeFinalDefault` only fills days whose `final_status` is still `null`; any value the GM has explicitly set via `:update_final_days` during `:ready_for_availability` is preserved. Applies `fan_out_notification(:schedule_posted)`. Sets `status: :posted` and `posted_at: now()`. |
| `:update_final_days` | update | `final_days :: list of {day, status}` | Asserts `status in [:ready_for_availability, :posted]`. Patches `ScheduleDay.final_status` for each day. No notification. Used by the GM both pre-post (in the Scheduling View while still `:ready_for_availability`) and post-post (silent edits). |
| `:update_final_days_and_notify` | update | as above | Asserts `status == :posted`. Patches as above, then `fan_out_notification(:schedule_updated)`. Notify-on-update is meaningful only after posting. |
| `:delete` | destroy | `confirmation :: :string` | Validation: `confirmation == "delete"`. Cascades `schedule_days`, `participants` (and their `participant_days`), and removes related `Notification` rows in the action callback. |
| `:list_for_player_character` | read | `player_id`; filter on `participants.player_id == player_id`; filter `status != :preparing`; sort `year DESC, month DESC` | Player-side; for the per-character schedule list. |
| `:get_for_player_character` | read | `id`, `player_id`; filter as above | Player-side; loads `schedule_days` (final_status only — gm_status not exposed except for the GM-NA-derived day-disabled flag) and the actor's `participant` + `participant_days`. |

### Policies

```
policies do
  bypass actor_attribute_equals(:_internal?, true) do
    authorize_if always()
  end

  policy action(:initiate) do
    authorize_if expr(game.owner_id == ^actor(:id))
  end

  policy action([:list_for_game, :list_for_game_top_six, :get_for_game,
                 :set_gm_day, :transition_to_ready_for_availability,
                 :post, :update_final_days, :update_final_days_and_notify, :delete]) do
    authorize_if expr(game.owner_id == ^actor(:id))
  end

  policy action([:list_for_player_character, :get_for_player_character]) do
    authorize_if expr(exists(participants, player.user_id == ^actor(:id))
                      and status != :preparing)
  end
end
```

### State machine

```text
preparing ──:transition_to_ready_for_availability──► ready_for_availability
                                                              │
                                                              :post
                                                              ▼
                                                            posted
                                                              │
                              ┌──:update_final_days ─────────┤
                              │  :update_final_days_and_notify│
                              ▼                               │
                            posted (Final values mutated) ◄──┘
```

Any state may transition to "deleted" via `:delete` (no soft-state).

## Resource: `GameNight.Schedules.ScheduleDay`

One row per (Schedule, day-of-month). Holds GM availability and the GM's Final decision.

### Attributes

| Name | Type | Constraints | Notes |
| --- | --- | --- | --- |
| `id` | `:uuid` | primary key | |
| `schedule_id` | `:uuid` | required, FK → `schedules.id`, ON DELETE CASCADE | |
| `day` | `:integer` | required, 1..31 | |
| `gm_status` | `:atom` | required, default `:NA`, `one_of: [:NA, :I, :A, :IF]` | |
| `final_status` | `:atom` | nullable, `one_of: [:NA, :A]` | null until `Schedule.post` runs `ComputeFinalDefault` |
| `inserted_at` / `updated_at` | timestamps | | |

### Calculations

| Name | Type | Source | Public? | Loaded by default? |
| --- | --- | --- | --- | --- |
| `final_note_kind` | `:atom` | `GameNight.Schedules.Calculations.FinalNoteKind` | yes | no (Scheduling View loads on demand) |
| `final_note_label` | `:string` | derived from `final_note_kind` + IF participant names | yes | no |

### Relationships

- `belongs_to :schedule, Schedule` (required)
- `many_to_many :participant_days, ParticipantDay, through: …` — but in practice the Scheduling View loads `schedule.participants -> participant_days filter day` rather than via this rel; this helper is defined only if telemetry surfaces a need.

### Identities

- `unique_per_schedule_day`: `[:schedule_id, :day]`.

### Actions

| Name | Type | Args | Notes |
| --- | --- | --- | --- |
| `:read` | read | implicit | Reads ride parent `Schedule` policies (no public list endpoint). |
| `:set_gm_status` | update | `status` | Internal; called by `Schedule.set_gm_day` change. |
| `:set_final_status` | update | `final_status` | Internal; called by `Schedule.post`, `Schedule.update_final_days`, and `Schedule.update_final_days_and_notify` changes. |

### Policies

```
policies do
  bypass actor_attribute_equals(:_internal?, true) do
    authorize_if always()
  end

  policy action(:read) do
    authorize_if expr(schedule.game.owner_id == ^actor(:id))
    authorize_if expr(exists(schedule.participants, player.user_id == ^actor(:id))
                      and schedule.status != :preparing)
  end

  policy action([:set_gm_status, :set_final_status]) do
    authorize_if expr(schedule.game.owner_id == ^actor(:id))
  end
end
```

### Field policies

`gm_status` is field-policy-gated: visible to the GM always; visible to participants only as a derived "is this day locked NA?" boolean exposed via a calculation `gm_locked_na :: :boolean = expr(gm_status == :NA)`. The raw `:I`/`:A`/`:IF` values are not exposed to participants — they don't need them, and not exposing them avoids any future "the GM was Ideal but I marked NA" social pressure.

```
field_policies do
  field_policy :gm_status do
    authorize_if expr(schedule.game.owner_id == ^actor(:id))
    # Other readers receive nil; the gm_locked_na calculation gives them what they need.
  end
end
```

## Resource: `GameNight.Schedules.ScheduleParticipant`

One row per (Schedule, Player) — links a player's character to a schedule.

### Attributes

| Name | Type | Constraints | Notes |
| --- | --- | --- | --- |
| `id` | `:uuid` | primary key | |
| `schedule_id` | `:uuid` | required, FK → `schedules.id`, ON DELETE CASCADE | |
| `player_id` | `:uuid` | required, FK → `players.id`, ON DELETE RESTRICT | Player removal is intercepted in application code (see "Player-removal handling" below) so non-posted schedules' participants are cascade-deleted while posted schedules' participants are preserved with `np_only` flipped to `true` and `submitted_at` nulled. |
| `submitted_at` | `:utc_datetime_usec` | nullable | set by `set_status` only after `Set Availability` action; not by every cell change |
| `joined_at` | `:utc_datetime_usec` | required, default `now()` | |
| `is_late_join?` | `:boolean` | required, default `false` | |
| `np_only?` | `:boolean` | required, default `false` | true when participant joined a `posted` schedule |

### Relationships

- `belongs_to :schedule, Schedule` (required)
- `belongs_to :player, GameNight.Games.Player` (required)
- `has_many :participant_days, ParticipantDay`

### Identities

- `unique_per_schedule_player`: `[:schedule_id, :player_id]`.

### Player-removal handling

When a `GameNight.Games.Player` row is destroyed, a `before_action` on the Player resource (introduced by this feature) iterates that player's `ScheduleParticipant` rows and:

- For participants whose `schedule.status` is `:preparing` or `:ready_for_availability`: destroys the participant (which DB-cascades its `participant_days`).
- For participants whose `schedule.status` is `:posted`: updates the participant in place — `np_only: true`, `submitted_at: nil`, every `participant_day.status` set to `:NP` via `ParticipantDay.bulk_set_to_np` (system action, T150).

This preserves historical truth on posted schedules while keeping non-posted rosters clean. The FK on `schedule_participants.player_id` is `ON DELETE RESTRICT` precisely to force this application-level path. See [research.md §6](./research.md).

### Actions

| Name | Type | Args | Notes |
| --- | --- | --- | --- |
| `:list_for_schedule` | read | filter on `schedule_id`; sort `joined_at` | GM-only and participant-self (filtered to own row). Loads `player`, `participant_days`. |
| `:list_for_my_schedules` | read | filter on `player.user_id == ^actor(:id)`; not used by primary flows but reserved for cross-cutting reads. | |
| `:set_submission` | update | none (sets `submitted_at = now()` if not already set) | Authorized to the participant only. Idempotent. |
| `:send_reminder` | update | none | GM-only. Triggers `fan_out_notification(:schedule_reminder, [participant])`. No `submitted_at` mutation. No rate limit (FR-038). |

### Policies

```
policies do
  bypass actor_attribute_equals(:_internal?, true) do
    authorize_if always()
  end

  policy action(:list_for_schedule) do
    authorize_if expr(schedule.game.owner_id == ^actor(:id))
    authorize_if expr(player.user_id == ^actor(:id))
  end

  policy action(:set_submission) do
    authorize_if expr(player.user_id == ^actor(:id)
                      and schedule.status == :ready_for_availability
                      and np_only? == false)
  end

  policy action(:send_reminder) do
    authorize_if expr(schedule.game.owner_id == ^actor(:id)
                      and np_only? == false
                      and is_nil(submitted_at))
  end
end
```

## Resource: `GameNight.Schedules.ParticipantDay`

One row per (ScheduleParticipant, day-of-month). Holds the participant's per-day status.

### Attributes

| Name | Type | Constraints | Notes |
| --- | --- | --- | --- |
| `id` | `:uuid` | primary key | |
| `participant_id` | `:uuid` | required, FK → `schedule_participants.id`, ON DELETE CASCADE | |
| `schedule_id` | `:uuid` | required, FK → `schedules.id`, ON DELETE CASCADE | denormalised per [research.md §16](./research.md) |
| `day` | `:integer` | required, 1..31 | |
| `status` | `:atom` | required, default `:NA`, `one_of: [:NA, :I, :A, :IF, :NP]` | NP only valid when participant is `np_only?: true` |
| `inserted_at` / `updated_at` | timestamps | | |

### Relationships

- `belongs_to :participant, ScheduleParticipant` (required)
- `belongs_to :schedule, Schedule` (required) — denormalised
- (no direct relation to `ScheduleDay`; the join uses `schedule_id + day`)

### Identities

- `unique_per_participant_day`: `[:participant_id, :day]`.

### Validations

- On any create/update: `participant.schedule_id == schedule_id` (the denormalisation invariant). Tested.
- On `:set_status`: rejects if `participant.np_only? == true` (NP cells are immutable).
- On `:set_status`: rejects if the matching `ScheduleDay.gm_status == :NA` (the GM-locked-NA rule).
- On `:set_status`: rejects if `participant.schedule.status != :ready_for_availability`.

### Actions

| Name | Type | Args | Notes |
| --- | --- | --- | --- |
| `:list_for_participant` | read | filter on `participant_id`; sort `day` | Participant-self or the GM. |
| `:set_status` | update | `status :: :NA \| :I \| :A \| :IF` | Participant-only. Validates per above. |
| `:bulk_set_to_na` | update (system) | `day :: integer`, `schedule_id` | Internal; called by `CascadeGmNa` when GM flips a day to NA. Bypasses policies via `_internal?: true`. |
| `:bulk_set_to_np` | update (system) | `participant_id` | Internal; called by `MarkDaysNp` when a late joiner is added to a posted schedule. |

### Policies

```
policies do
  bypass actor_attribute_equals(:_internal?, true) do
    authorize_if always()
  end

  policy action(:list_for_participant) do
    authorize_if expr(participant.player.user_id == ^actor(:id))
    authorize_if expr(participant.schedule.game.owner_id == ^actor(:id))
  end

  policy action(:set_status) do
    authorize_if expr(participant.player.user_id == ^actor(:id))
    forbid_if expr(participant.np_only? == true)
    forbid_if expr(participant.schedule.status != :ready_for_availability)
  end
end
```

(`set_status`'s "GM-locked-NA" check is enforced via a validation, not a policy, because it is a content rule rather than an authorisation rule.)

## Cross-resource update: `GameNight.Notifications.Notification`

Add four entries to the existing `kind` constraint:

```
attribute :kind, :atom do
  allow_nil? false
  constraints one_of: [
    # existing from feature 002 …
    :game_invitation,
    # new for feature 003:
    :schedule_ready_for_availability,
    :schedule_posted,
    :schedule_updated,
    :schedule_reminder
  ]
end
```

`subject_type`/`subject_id` point at the `schedules` table for all four new kinds. `payload` carries `{schedule_id, schedule_name, game_id, game_name}` so the bell + `/notifications` page render without an extra fetch. The `resolved_at` semantic from feature 002 does not apply to schedule notifications (they are informational and don't have an accept/decline counterpart) — the bell shows them as read once the user opens the bell or visits the linked schedule, using the existing `mark_read` action.

## Cross-resource update: `GameNight.Games.Game`

Add `has_many :schedules, GameNight.Schedules.Schedule`. No policy change is needed — `Schedule` policies bottom out on `schedule.game.owner_id == ^actor(:id)` and `exists(participants, …)`, so adding the relation does not expose new attributes.

## Migration order

`mix ash.codegen` will produce one combined migration that orders DDL as:

1. `schedules` (FK to `games`).
2. `schedule_days` (FK to `schedules`).
3. `schedule_participants` (FK to `schedules`, FK to `players`).
4. `participant_days` (FK to `schedule_participants`, FK to `schedules`).
5. Indexes (per [research.md §14](./research.md)).
6. `notifications.kind` constraint update (add the four new atoms).

Resource snapshots land at `priv/resource_snapshots/repo/{schedules,schedule_days,schedule_participants,participant_days}/`.
