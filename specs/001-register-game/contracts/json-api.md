# Contract: JSON:API surface for Game

**Feature**: 001-register-game
**Data model**: [../data-model.md](../data-model.md)

This document describes the JSON:API routes generated by the
`json_api` block on `GameNight.Games.Game` and wired through
`GameNightWeb.AshJsonApiRouter`. The generated OpenAPI spec is the
enforced source of truth; this file exists so planning and review
can be done without reading the regenerated OpenAPI on every change.

## Mount point

- Domain: `GameNight.Games` registered in
  `GameNightWeb.AshJsonApiRouter` (currently `domains: [GameNight.Telemetry]`;
  Phase 1 extends to `domains: [GameNight.Telemetry, GameNight.Games]`).
- All routes are reached under `/api/json/games/**`, mounted via the
  existing `forward "/", GameNightWeb.AshJsonApiRouter` in the `/api`
  scope.
- Pipeline: `:json_api_browser` (new, same as `:auth_browser` without
  the rate limiter — accepts JSON, loads the session, sets the actor).
  Added in Phase 1 work per plan.md §Constitution Check Principle II.

## Routes

| Method | Path                                   | Action                | Notes                                                                     |
|--------|----------------------------------------|-----------------------|---------------------------------------------------------------------------|
| GET    | `/api/json/games/active`               | `:list_mine_active`   | Index alias (Ash `index` directive `route: "/active"`).                   |
| GET    | `/api/json/games/all`                  | `:list_mine`          | Index alias (`route: "/all"`).                                            |
| GET    | `/api/json/games/:id`                  | `:get_mine`           | Standard JSON:API `:get`.                                                 |
| POST   | `/api/json/games`                      | `:register`           | Standard JSON:API `:post`.                                                |
| PATCH  | `/api/json/games/:id`                  | `:update`             | Standard JSON:API `:patch`.                                               |
| DELETE | `/api/json/games/:id`                  | `:destroy`            | Standard JSON:API `:delete`.                                              |

All routes require an authenticated actor. An anonymous caller
receives 401; an authenticated caller attempting to access another
owner's row receives 404 (the ownership filter makes "exists but
forbidden" indistinguishable from "does not exist" at the Ash layer).

## Example envelopes

### `GET /api/json/games/active`

**Request** (authenticated via session cookie):

```http
GET /api/json/games/active HTTP/1.1
Accept: application/vnd.api+json
```

**Response — user has active games**:

```json
{
  "data": [
    {
      "type": "game",
      "id": "4d3…",
      "attributes": {
        "title": "The Lost Mines of Phandelver",
        "description": "Opening adventure for our Tuesday group.",
        "status": "active",
        "inserted_at": "2026-04-20T18:12:05.123Z",
        "updated_at": "2026-04-23T09:30:11.008Z"
      },
      "relationships": {
        "owner": {
          "data": { "type": "user", "id": "aa2…" }
        }
      }
    }
  ]
}
```

**Response — user has no active games** (200 with empty data):

```json
{ "data": [] }
```

### `POST /api/json/games`

**Request**:

```http
POST /api/json/games HTTP/1.1
Content-Type: application/vnd.api+json
Accept: application/vnd.api+json
X-CSRF-Token: …
```

```json
{
  "data": {
    "type": "game",
    "attributes": {
      "title": "Curse of Strahd",
      "description": "Gothic horror campaign, rotating players.",
      "status": "active"
    }
  }
}
```

**Response (201)**:

```json
{
  "data": {
    "type": "game",
    "id": "5ab…",
    "attributes": { "...": "..." },
    "relationships": {
      "owner": { "data": { "type": "user", "id": "<actor-id>" } }
    }
  }
}
```

The `owner` relationship is server-set. Clients that include an
`owner` relationship in the request body MUST be ignored or
rejected at the action-accept boundary — `relate_actor/1` is
the authoritative writer.

### `PATCH /api/json/games/:id`

**Request**:

```json
{
  "data": {
    "type": "game",
    "id": "5ab…",
    "attributes": { "status": "paused" }
  }
}
```

**Response (200)**: updated game resource (same shape as `POST`
response).

If the request body attempts to change `owner` relationship, the
server MUST ignore it — the `:update` action's `accept` list
excludes `:owner_id`, so the attribute is inaccessible via the
action interface.

### `DELETE /api/json/games/:id`

**Request**: no body.

**Response (204)**: no body.

### Errors

All error responses follow the JSON:API error envelope and map to
stable codes:

| Status | Code                   | When                                                                          |
|--------|------------------------|-------------------------------------------------------------------------------|
| 401    | `not_authenticated`    | No session; no actor on the connection.                                       |
| 404    | `not_found`            | The resource does not exist OR exists but belongs to a different owner.       |
| 422    | `invalid_attribute`    | Validation failure (e.g., empty title, unknown status). One error per field.  |
| 429    | `rate_limited`         | Not applied in v1; placeholder for if/when JSON:API falls under the limiter.  |

## OpenAPI

`open_api_spex` regenerates the OpenAPI 3 document for the JSON:API
router on compile. The drift gate (`mix ash.codegen --check` +
`mix ash_typescript.codegen` + `git diff --exit-code`) ensures the
committed spec matches the live resource.

## Test strategy

- **Request-level tests** (`test/game_night_web/controllers/games_request_test.exs`):
  For each route, one authorized case ("the owner can …") and one
  unauthorized case ("a different user gets 404" / "an anonymous
  caller gets 401"). Each test uses `Phoenix.ConnTest.conn` through
  the real endpoint.
- **Policy tests** (`test/game_night/games/game_test.exs`): exercise
  the Ash action layer directly (`Ash.read!/Ash.create!/…`) with
  explicit actors to prove policies behave the same regardless of
  transport.
