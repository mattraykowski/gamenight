# Phase 1 Data Model: Register Game

**Feature**: 001-register-game
**Plan**: [plan.md](./plan.md)

Single new resource: `GameNight.Games.Game`, hosted in a new
`GameNight.Games` domain. No other schemas are added or modified.

## Entity: Game

A registered game-night context owned by one GM (User). Every action
is scoped to the owner by policy (see [research.md §5](./research.md)).

### Attributes

| Name           | Type          | Nullable | Public? | Constraints / Notes                                                                                     |
|----------------|---------------|----------|---------|---------------------------------------------------------------------------------------------------------|
| `id`           | `uuid`        | no       | yes     | Primary key. Generated by `uuid_primary_key`.                                                           |
| `title`        | `string`      | no       | yes     | `constraints min_length: 1, max_length: 120` — matches spec Assumption.                                 |
| `description`  | `string`      | yes      | yes     | `constraints max_length: 2000`. Treated as plain text by the SPA (no markdown rendering in v1).         |
| `status`       | `atom`        | no       | yes     | `constraints one_of: [:active, :paused, :cancelled, :completed]`, `default :active`.                    |
| `owner_id`     | `uuid`        | no       | no      | FK to `users.id`. Set on create via `change relate_actor(:owner)`. Excluded from `:update` accept list. |
| `inserted_at`  | `utc_datetime_usec` | no | yes     | `create_timestamp`.                                                                                     |
| `updated_at`   | `utc_datetime_usec` | no | yes     | `update_timestamp`. Drives the default sort for `list_mine` / `list_mine_active`.                       |

### Relationships

| Name     | Type        | Target                      | Required | Notes                                                                                   |
|----------|-------------|-----------------------------|----------|-----------------------------------------------------------------------------------------|
| `owner`  | `belongs_to`| `GameNight.Accounts.User`   | yes      | FK attribute `owner_id`. Read-only from the SPA; immutable after create.                |

### Postgres

```elixir
postgres do
  table "games"
  repo GameNight.Repo

  references do
    reference :owner, on_delete: :delete
  end

  custom_indexes do
    # Dashboard hot path: `list_mine_active` filters on owner + status
    # and orders by updated_at DESC. A composite index on all three
    # keeps the read index-only up to the configured dashboard cap.
    index [:owner_id, :status, :updated_at],
      name: "games_owner_status_updated_at_index"
  end
end
```

`on_delete: :delete` is chosen deliberately: if a user account is
deleted, their games go with them. The project overview explicitly
frames a Game as belonging to a GM; preserving orphaned games would
be misleading and violate the scoped-access guarantee.

### Actions

| Name                  | Type      | Accept                                 | Notes                                                                                   |
|-----------------------|-----------|----------------------------------------|-----------------------------------------------------------------------------------------|
| `:read`               | `read`    | —                                      | Base generic read. Policies ensure the actor sees only their own rows.                  |
| `:list_mine_active`   | `read`    | —                                      | `prepare build(filter: [status: :active], sort: [updated_at: :desc])`.                  |
| `:list_mine`          | `read`    | —                                      | `prepare build(sort: [updated_at: :desc])`.                                             |
| `:get_mine`           | `read`    | `argument :id, :uuid, allow_nil?: false` | `get? true`, `filter expr(id == ^arg(:id))`.                                            |
| `:register`           | `create`  | `[:title, :description, :status]`      | `change relate_actor(:owner)`.                                                          |
| `:update`             | `update`  | `[:title, :description, :status]`      | `require_atomic? true`. Explicitly excludes `:owner_id`.                                |
| `:destroy`            | `destroy` | —                                      | Hard delete (spec Assumption). Cascade via Postgres FK is N/A since Game has no children in v1. |

### Policies

Per-action, deny-by-default. Policy block (in full) lives at
[research.md §5](./research.md); semantics summary:

- `read` (and every named read that inherits it): authorized iff
  `owner_id == ^actor(:id)`.
- `register`: authorized iff `actor_present()`. No ownership check
  needed because the row does not exist yet; `relate_actor/1` sets
  the owner atomically in the same transaction.
- `update`, `destroy`: authorized iff `owner_id == ^actor(:id)`.

### State transitions

The `status` field has no enforced lifecycle (spec Assumption). Any
of the four values may transition to any other value via the
`:update` action, subject to the ownership policy. The SPA status
`<Select>` exposes all four options in the edit form.

### Validation rules (derived from spec requirements)

- **FR-002**: `title` is `allow_nil? false` with `min_length: 1`.
  The SPA's Zod schema enforces the same rule at the form boundary.
- **FR-002**: `status` is one of the four allowed atoms; the form's
  `<Select>` exposes exactly those options.
- **FR-003, FR-011, FR-015, FR-019**: every action's policy filters
  by `owner_id == ^actor(:id)`, making cross-owner access
  indistinguishable from "not found" at the Ash layer
  (Ash returns an empty list or `:not_found` — the JSON:API /
  RPC layer surfaces a 404 or equivalent).

### JSON:API serialisation

- Resource type: `"game"` (kebab-case plural applied automatically).
- Exposed attributes: `title`, `description`, `status`, `inserted_at`,
  `updated_at`. `owner_id` is not exposed as an attribute; the
  relationship `owner` serves that role.
- Exposed relationships: `owner` (read-only; the caller cannot change
  it via PATCH).

Route definitions live in [contracts/json-api.md](./contracts/json-api.md).

### `ash_typescript` RPC surface

The `GameNight.Games` domain's `typescript_rpc do ... end` block
exposes each action under a kebab-case name matching the action:

- `listMineActive`, `listMine`, `getMine`
- `registerGame` (named to avoid collision with JS `register`
  keyword aliasing), `updateGame`, `destroyGame`

Actions and their argument/return types are covered in
[contracts/rpc.md](./contracts/rpc.md).
